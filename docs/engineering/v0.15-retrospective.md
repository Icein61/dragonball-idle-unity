# v0.15.0–v0.15.5 开发复盘

本阶段完成悟饭与克林的正式接入，迭代图鉴交互、战斗状态、母表配置和角色动作。工作范围与验证以各版开发单为准。[版本开发单索引](../release-plans/README.md)

## 从工作簿到运行配置

- 使用 [角色工作簿](../../outputs/character/character.xlsx)「角色设计」的编号建立稳定映射。名字、时期称号、稀有度、类型、上线状态、身份标签及玩家展示技能随表内内容更新。当前生效的技能规则和图标写进 `RoundKits.json`，卡片元数据写进 `RoundSheetCatalog.cs`。
- 新角色先有稳定 CardId、正式战斗素材和 [素材绑定](../../Tools/round-character-assets.json)，再按表进入运行名单。新的技能句式或行为需要一个明确的解析与结算实现。构建预检会指出待实现的源单元格。
- 立绘回填只替换该卡的绘图引用和图片。保存用户原有复选框、合并区和样式。有写回时在 `.validation` 留原工作簿备份，重复构建无需重写工作簿。
- Windows 构建用 `Tools/build-windows.ps1`，正式归档用 `Tools/package-windows.ps1`。同步可以用 `Tools/sync-character-sheet.ps1 -Check` 单独核对。Python 3 可通过命令行参数或环境变量指定，脚本仅依赖标准库。

## 动作与交付经验

- 按相同种子复现 Demo 的阵容和手位。定向场景继续使用固定夹具，避免随机参战角色影响动作、音效或 Buff 的验证。
- 加速优先测量动作空档和战斗结算，保留技能聚气、接触与收招关键点。跑姿测试应读取正在绘制的姿态与脚底锚点。
- 回合效果各份独立到期。条件触发、伤害及回合结算先在纯逻辑验证，后台画面检查对应动作和状态出现时机，Windows Player 检查构建中的真实资源和存档入口。分别记载观察到了什么。
