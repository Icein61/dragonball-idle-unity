# 技能图标、动作和特效

## 制作单

每项资产记录版本、`CardId`、招式标识、简表工作表及具体单元格、招式名称、玩家属性、动作描述、参考图、制作状态和预览入口。设计空缺时在制作单标为草案或待填写。被动按实际触发时机设计可读反馈。

## 技能图标

- 每项技能一个图标。挑选最能辨识动作或效果的主体，统一轮廓和安全留白。在 64 像素尺寸先检查识别度。
- 图标主体应与游戏文案和演出一致。用墨青底色、暖金轮廓或项目现有容器承接，留出四角的小圆角空间。
- 交付透明 PNG，保留原稿。记录裁切区域、透明边界和导入尺寸。若按图集供稿，同张表的区域必须互不重叠。

## 姿态与动画

1. 以同卡战斗全身形象定相机、比例、朝向、落地基线和参考锚点。站立待机与偶发待机独立成段。入场、触发、受击、收招、回位和中断的连接应可辨认。
2. 首轮交付可逐帧查看的关键帧。交代预备、铺垫、出手、命中、余势和回位。检查肢体、足底、连续动作方向、服装和小尺寸轮廓。多段攻击逐段检查，条件分支单独演示。
3. 关键帧获认可后，补转重心、手脚过渡、动势和衣摆。用户要求采用低频动画充分表现各招式，时长按招式重点分配。起手、命中和收势保留可读的停顿，关键转折之间补足过渡帧。首轮秒数属于制作默认值，可随试玩修整。
4. 特效独立于人物，以手部、足底、受击点或目标行等锚点触发。命中、状态变化和演出事件一一对应。收尾能退出或回到待机，减少动效时保留必要读数。
5. 接入前核对角色帧、图标、特效、缺帧、帧边界和授权来源。接入后分别记录无窗口验证与可见试玩，按[验收场景](../../verification/acceptance.md)核对。

图像源稿、关键帧预览与已导入运行资源均保留版本标识。在开发单写明这次实际达到的阶段。

## 受击与状态过渡

- 分别制作站立受击、击退、小浮空、大浮空与倒地的短姿势段，设阶段起点、脚底基准、落点和回位姿势。进场、战败独立制作。
- 连续命中以该帧已经显示的姿势和位置作为衔接起点。再次命中同一状态时也重新响应，从当前姿势进入该状态的出力段。支持跨状态衔接，避免在两个事件之间强制回到原始站位或站立帧。
- 小浮空和大浮空以横向坠落中腹部挨上击为动作基准。腹部带动身体、头与四肢滞后，两档体现不同弯曲和位移。击退朝向攻击来源侧，倒地脸朝上。预览时检查四肢轮廓、服装和位移顺序。
- 近身攻击素材登记拳、脚或武器的实际接触锚点，与受击实画相接。不同阵位、镜像与追打高度都核对接触帧。特效继续以实际动作锚点触发。
- 验证从五种状态到五种状态的有序组合，覆盖五种同状态重复。动作、位移、受击特效、血量更新和声音使用各自的战斗命中或落地时点。

## 视频参考

- v0.13.3 起，制作单先核对角色简表填写的技能属性及动作描述。简表明确的条目按表执行，空缺以同卡视频为准。记录文件名、标记帧、动作阶段、命中窗口和声音节拍。
- `Assets/DragonIdle/Resources/Videos` 中的原片供本地制作参考，从版本提交和 Windows 包中排除。Windows 构建使用 `Tools/build-windows.ps1` 从临时工程打包已导入的运行资源。Player 回归检查参考视频资源为空。

## 招式音频

- v0.13.4 起，角色语音与招式音效优先查找素材来源视频里的可用片段。记录来源文件、片段和用途。缺合适素材时在音频配置保留空路径，并在制作单标注留白。合成中文版和自行合成的占位音效退出本流程。
- 保留各招式的音频事件时点。空路径在播放时跳过，动作与特效继续独立运行。核心规则、音频导入和实际听感分别验收。

## v0.13.5 动作节奏、模型与来源音效

- 先标准备、爆发、接触短停、余势和回位时点。相邻动作段按发力节拍分配时长。格斗接近、重击、蓄力和释放应有速度对比。用脚底验证支撑和地面投影，分别记录近身路径、骨骼或帧姿态及触发特效的锚点。
- 可按构图、手脚、透视或连续性选用适合的绘图和动画模型，统一 C 版造型、机位及素材来源。逐帧检查关键支撑点及尺寸，实机演出单独验收。
- 视频音效优先尝试按动作时点裁切、检查声道和可用独立音源。不能得到可用的音效时，在制作单记录片段、尝试和留白原因。

## v0.13.7 圆角与音频来源

- 按用户要求，状态条及其他边框默认采用圆角，具体控件有明确规格时以其规格为准。窄条的轨道和填充共用相同圆角轮廓。
- 新增音效按用户指定的《Dragon Ball Xenoverse 2》音频库查找。记录片段来源和运行事件。接入状态按可用素材如实登记，本版追打、技能、入场和受击事件留白。
- 连打提示白光贴合角色上半身，在启动动作前迅速出现和消退。图集使用原始尺寸，登记透明通道、裁切及锚点，验证导入后的实际纹理尺寸。

## v0.13.8 本机音频接入

- 用户已指定的本机音频库可直接用于对应招式。登记源文件和事件，按实际动作对齐时点并用配置控制增益。
- 受击语音从受击角色的素材中选择。规避、治疗和跳过的动作不播放受击语音。

## v0.13.9 攻击范围与特效

- 制作技能动作和特效前读取该卡配置中的目标范围。分别核对单体、横排及其他范围的画面覆盖。
- 横排光波按配置匹配目标排，横向幅度覆盖完整一排，包括空位。跨排情况优先在释法前对齐。近端与掌心相接，边缘圆润，尾部自然衰减。特效覆盖与实际伤害结算分别验收。

## v0.13.10 战斗图标与镜头

战斗技能名牌从该卡对应招式的素材读取图标。使用原图集时登记区域与尺寸。缺图标的招式显示名称，继续在制作记录里保留补图状态。名牌使用固定锚点。必杀镜头核对推近和回位两段，动作结束回到释放前的视角。

## v0.14.5 角色图标与当前音频库

- 有角色入画的技能图标可用适度 Q 版表情和比例。保持角色时期、服装、动作与技能辨识度。双手交替发射类图标在一张图里用错开的出手和弹道表现时序。
- 角色语音、技能和通用战斗音效的制作入口为主项目的 artifacts/xenoverse2-audio/赛亚人篇-角色音频素材库。先读「素材库索引.txt」定位角色与技能，再用「逐条音轨索引.txt」核对音轨、事件和来源。运行时读取已导入的 Unity 资源。
- 持续性特效按角色战斗状态进入和退出。走查对方行动、受击、跳过、减少动效和取消。跑步帧用实际移动时间计步，避免长距离攻击被统一的短动作时长挤压。

## v0.15.0 技能图标写实比例与透视

- 角色图标采用写实的人体比例和可靠透视。出手前检查肩、肘、腕和两手的空间关系，选择能看清技能的机位。
- 构图以技能为重点。保留服装、发型和必要的角色特征，压低背景、远侧肢体或次要细节。64 像素核对动作及弹道辨识度。

## v0.15.1 现行素材规则

- 角色立绘和招式素材统一用本项目 C 版手绘漫画画风。按系统已有立绘的线条、阴影和人物比例处理。去除 Q 版夸张和写实渲染，保留角色这一时期的发型、服装和动作辨识点。
- 图标以技能瞬间或机制效果为主体，简化次要肢体和背景。在游戏缩略尺寸核对发力方向、特效轮廓和主要识别点。
- 同卡的图标、关键姿态、特效与音频分别记录触发和结算时点。源视频作为制作参考保留在本机，运行资产按导入路径登记。
