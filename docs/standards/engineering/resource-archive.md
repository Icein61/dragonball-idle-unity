# Unity 运行资源归档

以 Resources 键、原始项目路径和 Unity GUID 为同一资源的三个核对入口。候选项和保留项都写入清单。

1. 核对当前场景、Prefab、项目设置、资源 `.meta` 中的 GUID 和直接引用。检查工作簿绑定、运行配置、动态图集、动作与受击清单、声音清单及构建工具。把脚本拼接、按角色和稀有度加载、旧版回退及跨目录相对路径具体展开。
2. 有现行加载、回退或验证依赖的资源保留原位。仅被同批历史清单读取的资源可以成组归档，保留组内相对路径。区分旧制作出处、导入器匹配条件和实际运行入口。引用证据有疑点时保留资源并登记原因。
3. 将确认项移至 Unity 导入范围外的 `Art/Archive/<批次>/`。归档记录原路径、归档路径、Resources 键、SHA-256、原始文件和所有随迁 `.meta`。腾空目录的 `.meta` 同步归档。保持字节与路径层级，恢复时先检查目标冲突。
4. 按清单在隔离目录演练恢复，逐一复核文件哈希与 GUID。重新后台构建，向 `Tools/smoke-windows.ps1` 提供带 `resourceKeys` 的 `-ResourceArchiveManifest`，逐一检查归档资源是否仍可在 Player 加载，同时回归现行界面和战斗。记录结果与保留依据。

实例见 [v0.19.0 归档说明及恢复方法](../../../Art/Archive/V0190Resources/README.md)。参考视频另按[本地制作和历史恢复流程](../../engineering/handoff.md#参考视频的归档与本地清理)管理。
