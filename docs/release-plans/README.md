# 版本开发单

每个版本一份。新一轮的开发内容和修复意见写入 **[v0.18.1 版本开发单](v0.18.1.md)**。

- **版本开发内容**：写这版要做什么，先做什么，哪些内容保持不变，以及怎样算完成。空栏不视为已下达需求。
- **版本修复BUG**：试玩后或开发中，直接写「哪里要改 → 期望改成什么」。需要时附参考图、复现步骤或优先级。
- **落地记录**：由代理逐条回填状态、实际改动和验证；保留用户原文。状态可用「待处理 / 进行中 / 待验收 / 已完成 / 转入其他版本」。后两种注明验证结果或承接版本。

准备新版本时，从[模板](TEMPLATE.md)建立对应版本号的文件，更新本页和项目状态的当前入口。同一版本开发中的追加意见继续写在同一单；已发布版本的反馈也留在原单，如果要重新发包，修复进入新的补丁版本，旧标签和包保留。

发布说明仍放在 `Releases/`。历史单只提供补录入口，已交付内容以对应发布说明为准。
