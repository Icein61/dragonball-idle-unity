# v0.19.0 版本开发单

以 [v0.18.2 正式版本](https://github.com/Icein61/dragonball-idle-unity/releases/tag/v0.18.2) 为基准。本地开发源码已切换至 v0.19.0。经用户确认，先按下文实施顺序重构当前上线链路。

## 版本开发内容
  在之前的版本开发中，我陆陆续续发现了一些问题。
    - 素材
      - 立绘。立绘素材和技能图标基本需要反复修改，风格时常无法统一，且有一个最关键的问题：有时和原作差异巨大。
      - 小人。小人单个动作看起来可能没问题，但是小人的身高体型、肤色、装饰时常不统一，导致单个动作看起来是可行的，但是连贯起来就是需要重做的程度。
      - 冗余。有非常多的旧素材保留下来，不仅会占用空间，还会污染素材库。
    - 代码
      - 代码规范问题。硬编码、中文字符串太多，甚至有中文命名，这些都是极为不好的习惯。
      - 几乎没有读取配置表这样规范的写法。
    - 配置
      - 除了我的角色设计表，几乎没有专门供客户端代码读取的数据表。
    - 目录
      - 项目中的目录分级没有做好。
    - 开发流程
      - 目前几乎是我和单个agent一问一答式的开发，没有制定好完善的rules、skills、也没有多agent协同。
    - 总结
      - 这个版本我们先不做开发，做好代码重构，架构优化好、命名规范、代码质量提高；根据我的个人用配置表生成代码用的配置表，杜绝硬编码；订好一个规范的开发流程，实时更新和补充rules和skills。整个开发过程中的一切问题都可以和我讨论，你作为统筹，你可以生成其他agent对话，分别负责设计、美术、策划、程序、测试或者从中选取需要的会话，为了每个版本的目标高质量的执行下去。

## 实施顺序（已确认范围）

以 v0.18.2 为基线，重构当前上线的图鉴、编队、战斗和存档链路，保持玩法、界面表现和九张上线卡的规则。历史代码按现行链路的实际依赖处理。凡涉及改变玩法或存档行为的决定，先说明影响并取得用户确认。

| 顺序 | 工作 | 交付与验证 |
| --- | --- | --- |
| 1 | 建立回归基线，盘点硬编码、读表、资源入口和现用存档路径 | 保存核心检查、配表回读和 Windows 后台验证的结果。按模块登记调用方、数据源和风险。 |
| 2 | 重构页面路由与图鉴、编队共用入口 | 中文文案与程序标识分开。控制流使用稳定英文标识，现有布局、导航、筛选、阵位和保存交互按基线复核。 |
| 3 | 整理配置生成和运行时加载，再逐批迁移战斗配置 | [character.xlsx](../../outputs/character/character.xlsx) 是本轮唯一的个人配置表。保留用户填法和文案，经工具生成客户端读取的数据。技能、卡片、资源映射、时序和文案按各自用途组织。先迁移已确定的值，再处理需要用户确认的规则。 |
| 4 | 重构战斗与存档边界 | 模拟层继续负责结算，表现层消费结果。收拢当前存档的读写、备份和默认开局。以新档验收，旧版进度迁移不作为本版交付条件。改变存档格式、位置、清档触发方式或失败处理时先确认。 |
| 5 | 清点旧素材和目录依赖，分批归档 | 扫描 Unity 引用、配置、脚本加载、回退资源和构建工具。确认无运行依赖后移出运行目录，归档记录原路径、文件、.meta 和恢复方法。运行资产按角色和用途明确归属。 |
| 6 | 固化协作规则与技能，完成全链路回归 | 形成仓库内的配表、资源归档、角色素材质检和验收约定，随落地经验更新。以九卡、真实功能入口和隔离新档做整体回归。 |

| 分工 | 职责 | 交接证据 |

| 配置 | 保留 Excel 填写口径，整理生成映射、运行数据结构、校验和客户端加载。 | 源字段到生成字段的映射、可重跑命令与结果。 |
| 素材 | 盘点引用与历史资产，维护目录和可恢复归档，形成原作与全动作一致性核对标准。 | 资源清单、依赖证据、归档与恢复记录。 |

相互独立的核查可并行，同一文件的实现按负责人串行。配置和资源批次先提交引用关系与回归证据，再合并到运行链路。

### 验收标准

- **图鉴与编队**。九张上线卡、排序、筛选、切卡、收藏、技能描述及图标按发布版对照。拖放、换位、取消草稿和显式保存按现有规则执行。战斗 Demo 读取已保存阵容。
- **战斗**。在同一配置和固定随机种子下，手位、目标、连击、伤害、状态、追打、关键演出、音效事件和胜负对照基线。分别核对模拟、Unity 演出与无窗口 Player。
- **配置**。角色表沿用现有填法。相同输入重复生成结果一致。字段、稳定 ID、引用、数值单位和缺项都可校验。已有规则值迁移前后逐项对照。英文标识用于程序，中文文案面向玩家。
- **存档**。用独立新档验证首次启动、编队保存、重启读档与读写失败路径。用户已授权基础开发期间在每版打包时清理本项目本地存档以便从零试玩。开发和回归使用隔离档，涉及其他存档行为的调整先确认。
- **素材**。每批归档前核对直接引用、以名称加载、回退路径和验证工具，归档后可按清单恢复。现用资源仍完整加载。角色制作验收同时对照原作与同角色的待机、攻击、受击和复位，核对身高、肤色、服装和装饰。
- **交付**。记录核心检查、配置回读、Unity 后台构建和九卡 Windows 无窗口回归的实际结果。打包后检查 ZIP、版本及源码对应关系。开发单按批次记录结论。

### 现行链路交接

- [主页](../../Assets/DragonIdle/Presentation/ShellUI.cs)经 [PageRoute](../../Assets/DragonIdle/Presentation/PageRoutes.cs)进入[图鉴](../../Assets/DragonIdle/Presentation/GalleryUI.cs)及[编队](../../Assets/DragonIdle/Presentation/RoundFormationUI.cs)。图鉴、启动预载等共用 [PortraitKey](../../Assets/DragonIdle/Presentation/ChapterViews.cs)。角色表同步可用 `Tools/sync-character-sheet.ps1 -Check` 核对生成结果。
- 战斗入口加载 `RoundKits` 和 `RoundEncounters`。战斗 Demo 从 `Scenes` 选择场景并读取已保存阵容。推进战斗经 `ResolveStep`，按行动结果和快照驱动演出。[配置入口](../../Assets/DragonIdle/Presentation/RoundUI.cs) · [战斗 Demo](../../Assets/DragonIdle/Presentation/RoundDemoUI.cs) · [结算](../../Assets/DragonIdle/Core/RoundCombat.cs) · [演出调度](../../Assets/DragonIdle/Presentation/RoundPlayback.cs)。
- 启动时解析默认路径或显式 `-savePath`，随后由 `ProfileStore` 管理文件。编队保存继续经过 `Profile` 的阵容校验，客户端事务失败时还原内存状态。[启动与事务](../../Assets/DragonIdle/Presentation/DemoGame.cs) · [存档读写](../../Assets/DragonIdle/Presentation/ProfileStore.cs) · [阵容校验](../../Assets/DragonIdle/Core/RoundFormation.cs)。
- 用 `Tools/compare-round-traces.ps1` 复跑 v0.18.2 固定种子对照。用 `Tools/smoke-profile.ps1 -Executable <当前 Windows Player>` 复跑独立进程的隔离新档验证。
