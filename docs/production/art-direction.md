# 美术方向与制作流程

## 已确认目标
- 精美是核心要求；龙珠形象、原著阶段、招式辨识度优先。
- 手绘感，优先考虑3渲2，同时接受高质量2D。
- 参考Dokkan Battle的立绘质感、抽卡氛围、角色表现与招式演出。
- 用户可提供每个新角色的形象及登场阶段参考；目前授权代理自行寻找参考并制作原型。
- AI图像与音乐可使用；生成图片不等于模型、绑定、连续动作已完成。
- 16:9横屏，逐次聚焦，每次行动清楚且有分量；不能只有必杀值得观看。

## 首次路线验证
1. 首个样片角色阶段已明确：孙悟空，龙珠Z初期与比克联手迎战拉蒂兹。用户认可v0.2.0悟空样片的画风，要求沿此风格继续优化并由其挑选。
2. 相同角色、服装、姿势主题与场景做2D和3渲2目标样片。
3. 对比脸型、轮廓、服装、色彩、线条与阶段一致性。
4. 静态样片通过后补短动作验证：起手、攻击、命中、回位。
5. 由用户确定视觉偏好，再锁定主生产路线；在此之前只做不依赖路线的模拟和数据工作。
6. 不用一张概念图代替实际Unity表现的验证；区分概念、素材、动作和实机截图。

## 默认制作组织
- 每张卡使用稳定CardId；素材按CardId组织，不以人物名字作为唯一文件夹键。
- 保存角色参考清单、原始素材、生成提示词/模型信息（可得时）、切分/导入设置、版本说明。
- 记录素材来源与使用范围，避免换环境后丢失参考或误认原创来源。
- 身份标签在定义中维护，不能由美术名称或服装解析。
- 程序占位必须明显标注，不能宣称达到终版质量。
- 立绘展示、抽卡、详情、普通攻击、绝招、必杀分别验收。
- UI应清楚展示角色行动进度、怒气、目标、冷却、状态来源与期限。
- 美术冻结前不批量生成完整角色阵容，避免不同模型/风格混杂。
