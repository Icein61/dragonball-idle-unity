# UI打磨方向：简洁、美观、圆润

日期：2026-11-17（Asia/Shanghai）。分析基线：main 363aa54caafbbecb0f508e44fa9c5ccd3f096ebe，运行版本0.5.3。本文为下一阶段方案，未实施UI改版、未生成新PC包。

## 要求与基线

用户要求拉取最新Git并分析下一步开发，认为当前UI不够美观，要求参考热门手游，倾向简洁、美观、圆润。此方向已明确；下述配色、布局参数与顺序为代理建议，尚非用户逐项审美验收。

保留最新三卡用户技能原文、概念图绑定、龙珠爆裂激斗名称与图标；其他卡沿用已选C风格。UI改版不修改身份、数值和存档。保持横屏PC布局与鼠标/键盘操作。

## 源码分析

- GalleryUI使用uGUI，其余页面仍由DemoGame.OnGUI与GUI.skin.button绘制，两套组件不利于统一视觉与操作反馈。
- UPanel是纯色Image，无圆角sprite；卡面、正文、筛选与主操作多为类似深色矩形，主次区分不足。
- 图鉴卡片219×258，立绘区域191×127。对于2:3图片，等比显示宽度只有约85，主体占比偏小；前三张用户图比例不同，不能统一强制裁成2:3。
- 列表从参考画布y=349才开始，可滚区域478高；标题和多排筛选占用过多空间，关键词仅11号参考字号，小窗口可读性有风险。
- 详情正文滚动区域只有265高，属性说明、技能与规则多为连续段落，需要分层阅读。
- 选卡会RefreshGallery并ClearUI(gridRoot)，重建全部卡片。当前15卡不能据此断言卡顿，但应局部更新，减少后续扩充开销与焦点干扰。
- 本轮未显示游戏窗口，以上为源码可确认问题，不是v0.5.3真实渲染验收结论。

## 推荐方案（代理默认草案）

- 暖白/浅灰面板、深蓝灰文字和导航、橙色主操作、少量蓝色次级提示。稀有度用徽章与边缘点缀，减少大面积彩色框。
- 按钮圆角12～16、面板20～24（参考画布尺寸），标签可用胶囊形；8点间距体系，正文18～20、次级至少16。关键文字对比目标4.5:1。
- 卡面图像区域约占2/3，保留名称、版本、稀有度、上阵状态和2～3关键词。全图欣赏显示完整原图，缩略图逐卡设焦点，不裁掉标志性手势及技能主体。
- 搜索、排序与页签压缩为一排，额外条件进入筛选面板，已选条件可单独清除。
- 列表采用大卡网格；详情使用专用大区域，左侧完整大立绘、右侧概览/招式/培养/装备、底部固定主操作。返回恢复筛选、滚动、选择和焦点。
- 默认展示当前有效属性，基础/个人/编队拆解可展开。技能按条目组织，用户原文完整保留，运行数值解释单列，不能为了短文案修改技能语义。
- 统一悬停、按下、选中、禁用和键盘焦点；120～180ms短反馈，减少动效即时化。资源不足明确显示原因。

## 实施顺序

1. 第一阶段先完成公共导航外框与角色/图鉴：角色列表、概览、招式两屏样板，随后统一筛选、阵位与设置弹窗。继续uGUI，提取主题和圆角九宫格等公共组件，不新增UI框架。
2. 第二阶段统一编队、养成、装备，优先减少反复跳页与角色上下文丢失。
3. 第三阶段统一挑战、结算、召唤，再精修转场、音乐与反馈音；菜单音乐连续、失焦静音，高频操作不被长动画阻塞。

以现有功能打磨为主，不扩充角色/卡池/副本。先验证实际UI组件样板，再推广到全部页面；概念图不代替Unity实装。
