# 现有15卡重构设计流程

2026-11-16：用户要求新建角色设计配置表，由用户填写基本设计，代理润色、调整数值并实际落地，从当前15卡开始重构。这是新的开发优先级，不再先扩展角色或剧情。

填写文件：`outputs/character-rework-20261116/角色设计配置表.xlsx`。只编辑“填写设计”的黄色栏，可先提交一张。写清想实现的特色、招式、被动、队长与动作即可，数值允许留空交代理调整。空白代表未提供；明确写“沿用”才将该项旧方案作为新设计。蓝色栏由代理补充，不覆盖用户原话。灰色现状和“当前数值基线”是v0.5.2原型快照，不代表用户已确认新设计。

## 收到填写内容后

1. 按CardId对照用户原稿，保留原话；整理明确机制、触发条件、目标、费用、时长、例外与演出要求。合理细节自主默认，单独标注；不再逐项要求确认。
2. 用既有类别和贡献计时实现设计，补充属性强弱、招式倍率、冷却、怒气、触发条件与强度代价，记录修改原因。队长标签必须来自本人身份，定位词不创造新乘区。
3. 原CardId与人物/阶段不改指向。涉及新阶段/新人物时另建卡；旧成长、装备、预设及存档必须有迁移路径。
4. 将润色方案落实到角色定义、战斗逻辑、UI说明、立绘/小人动作、招式特效、获取及成长配置。表格本身不是运行配置，不会自动热更新；填表或文字润色不算角色已经实现。
5. 针对具体机制和极端组合做核心验证，比较胜率、行动数及团队收益；做Unity后台构建、隔离静音Player与存档迁移验证。没有模拟/真人证据不宣称2～3小时成长目标通过。
6. 在“落地追踪”逐项填写代码/动作/测试证据及版本提交。程序测试与可见观感分别记录；窗口权限仍未恢复。可玩版本按源码与PC包对应规则交付。

初始15卡均为“待填写”，没有冒充用户设计或已完成重构。重复卡分支可以在表中提案，但当前实现尚未完成，必须在追踪中保留真实状态。

## 基线与文件维护

`baseline-v052.json`从当前Core编译结果导出，包含15个唯一CardId、完整技能说明和队长数值；导出代码为Tools/CharacterDesignExport.cs。表内角色数据已与该快照逐卡映射。数据文件不是运行目录替代品。

用户填过的Excel必须增量编辑，不能用生成脚本覆盖；重构后旧基线保留，必要时另建新版本快照。首版创建与三页渲染检查已执行，未做可见Excel应用操作；本轮未改战斗/数值或生成新PC包。
